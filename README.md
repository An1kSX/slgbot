# SherLegal — бот для групп Telegram

Бот сохраняет текст, фотографии и документы из групп в JSON и HTML, отмечает
деловые обращения клиентов вне рабочего времени и отправляет автоответ.
Администраторам доступны список групп и удаление бота из группы;
суперадминистраторам — выгрузка чатов и ежедневный отчёт об обращениях.

## Что потребуется

- Linux-сервер с установленными Docker Engine и Docker Compose v2.
- Доступ сервера к Telegram и API OpenAI, а при сборке — к Docker Hub и PyPI.
- Учётные данные Telegram, минимум один Telegram ID суперадминистратора и ключ OpenAI.

Python и MySQL на сервер отдельно устанавливать не нужно. Compose запускает два
контейнера: `bot` и `mysql`. Входящие порты на сервере не публикуются.
Далее приведены команды для Bash; выполнять их из корня проекта.

## 1. Заполнить `.env`

При первой установке:

```bash
cp .env.example .env
chmod 600 .env
nano .env
```

Сохраните файл в UTF-8. При обновлении используйте существующий `.env`, не
заменяйте его шаблоном. Сам `.env`, сессии и рабочую переписку не включайте в
архив исходного кода для передачи.

| Переменная | Что указать |
| --- | --- |
| `API_ID`, `API_HASH` | Параметры приложения Telegram из раздела **API development tools** на [my.telegram.org](https://my.telegram.org). Это не токен бота. [Инструкция Telegram](https://core.telegram.org/api/obtaining_api_id). |
| `BOT_TOKEN` | Токен созданного бота из [@BotFather](https://t.me/BotFather). |
| `BOT_USERNAME` | Необязательно: username этого же бота без `@`. |
| `SUPERADMIN_IDS` | Числовые Telegram ID пользователей через запятую, например `111111111,222222222`. Минимум один. Не username и не номер телефона. |
| `ADMIN_IDS` | Необязательно: ID остальных администраторов через запятую. |
| `MYSQL_ROOT_PASSWORD` | Пароль администратора встроенной MySQL. |
| `MYSQL_PASSWORD` | Отдельный пароль пользователя БД, от имени которого работает бот. |
| `OPENAI_API_KEY` | Ключ для классификации обращений; у проекта должен быть доступ к выбранной модели. |

ID бота определяется автоматически из `BOT_TOKEN`. Переменная `BOT_USER_ID`
больше не нужна; её старое значение, если осталось в `.env`, игнорируется.

Для паролей удобно использовать две разные случайные строки, полученные двумя
вызовами `openssl rand -hex 24`. Значения со знаком `$` заключайте в одинарные
кавычки: Compose иначе выполняет подстановку переменных.
[Синтаксис `.env` в Docker Compose](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/).

Пустой `OPENAI_API_KEY` не мешает запуску, но отключает классификацию:
любой непустой текст, прошедший остальные проверки обращения, считается деловым.
Для штатной работы заполните ключ.

Остальные параметры можно оставить по умолчанию:

| Переменная | Значение / назначение |
| --- | --- |
| `COMPOSE_PROJECT_NAME` | `slgbot`. Определяет установку и имя тома БД; не менять после первого запуска. |
| `MYSQL_USER`, `MYSQL_DATABASE` | `slg_bot`. Пользователь и база создаются автоматически при первой установке. |
| `MYSQL_QUEUE_SIZE` | `10`, число соединений с БД. |
| `STAFF_MARKER` | `SLG`. Совпадение в имени, username или звании участника означает сотрудника. |
| `STAFF_USER_IDS`, `STAFF_USERNAMES` | Дополнительные сотрудники через запятую; usernames без `@`. |
| `WORKING_DAYS` | `0,1,2,3,4,5`: понедельник–суббота; `6` — воскресенье. |
| `WORK_START`, `WORK_END` | `09:00` и `18:00`. В 18:00 рабочее время уже закончено. |
| `APPEAL_REPORT_TIME` | `09:00`, ежедневный отчёт суперадминистраторам, включая выходные. |
| `APPEAL_COOLDOWN_SECONDS` | `54000`: интервал между автоответами в одной группе, 15 часов. |
| `APPEAL_AUTO_REPLY` | Текст автоответа клиенту. В шаблоне уже задан; при пустом значении используется стандартный ответ SherLegal. |
| `OPENAI_MODEL` | `gpt-5-mini`. |
| `LOG_ARCHIVE_TIME` | `00:00`, перенос завершившихся дней в архив. |
| `MAX_DOCUMENT_MB` | `50`, максимальный размер документа для скачивания в HTML-выгрузку. |
| `LOG_ZIP_PREFIX` | `slg_chats`, начало имени ZIP-файла. |
| `LOG_LEVEL` | `INFO`, подробность служебных логов. |

Время расписания, сообщений и дат выгрузки — **Asia/Tashkent**. Пути и адрес БД
в контейнерах уже заданы в `docker-compose.yml`; добавлять их в `.env` не нужно.

## 2. Подготовить папку данных

Контейнер бота работает с UID/GID `10001`. При новой установке на Linux создайте
каталоги с соответствующими правами:

```bash
sudo install -d -m 0750 -o 10001 -g 10001 data data/groups data/archive data/runtime
```

Это нужно сделать до запуска: автоматически созданная Docker папка может
принадлежать `root`, и бот не сможет записать сессию и логи.

## 3. Запустить

```bash
docker compose version
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 -f bot
```

`config --quiet` проверяет конфигурацию, не печатая значения секретов. При
незаполненных обязательных параметрах Compose укажет имя переменной.
После старта `mysql` должен стать `healthy`, а `bot` — оставаться `Up`, без
постоянных перезапусков. Первый запуск MySQL может занять некоторое время;
бот ждёт её готовности. Таблицы и записи администраторов создаются автоматически.
Для выхода из просмотра логов нажмите `Ctrl+C` — контейнеры продолжат работать.

Не запускайте второй экземпляр бота с той же папкой сессии.

## 4. Проверить в Telegram

1. Каждый администратор открывает личный чат с ботом и отправляет `/start`.
   Должно появиться меню. До этого бот может не суметь отправить личный отчёт.
2. Добавьте бота в тестовую группу и назначьте его администратором, чтобы он
   получал обычные сообщения участников. [Правила доставки сообщений Telegram](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).
3. Отправьте текст, фотографию и небольшой документ. Проверьте группу через
   кнопку «Список чатов».
4. От имени суперадминистратора нажмите «Выгрузить чаты». Распакуйте ZIP,
   откройте `chat_export/chat_export.html` внутри папки группы. Файлы HTML,
   `js`, `css`, `img` и `docs` должны оставаться вместе.
5. Проверьте автоответ на деловое сообщение от клиента вне рабочих часов.
   Сообщение сотрудника и повторное сообщение во время cooldown автоответа не вызывают.

Сам по себе статус контейнера `Up` ещё не подтверждает работу Telegram и БД:
проверка сообщения и выгрузки обязательна при приёмке.

## Где хранятся данные

```text
slgbot/                  код бота
  templates/             HTML, CSS, JS и изображения для экспорта
requirements/            зависимости приложения и тестов
tests/                   автоматические проверки
docs/                    документация для разработчика и история проекта
data/                    рабочие данные, не включаются в Git и образ
  groups/ДД.ММ.ГГГГ/chat_<ID>/
  archive/ДД.ММ.ГГГГ/chat_<ID>/
  runtime/               сессия Telegram, настройки меню, logs.log
.env.example             шаблон конфигурации
.env                     конфигурация конкретной установки
Dockerfile
docker-compose.yml
README.md
```

База MySQL находится отдельно, в Docker-томе `<COMPOSE_PROJECT_NAME>_mysql_data`.
Данные сохраняются при пересоздании контейнеров и обычном `docker compose down`.
**Не используйте `docker compose down -v`: это удаляет том базы.**

В 00:00 логи за 12 сентября переходят в `archive/12.09.ГГГГ`, даже если перенос
фактически выполнится уже 13 сентября. Новые сообщения сохраняются под новой
датой. Ручная выгрузка включает только текущий день по Ташкенту. Автоматической
отправки ZIP в полночь нет; прошлые дни автоматически не анализируются.
Архивы не удаляются по сроку хранения, поэтому следите за свободным местом.
Служебный `logs.log` ротируется: основной файл и две копии примерно по 5 МБ.

## Обслуживание и обновление

```bash
docker compose logs --tail=100 bot mysql   # последние сообщения
docker compose restart bot               # перезапуск с прежними настройками
docker compose stop                      # остановка без удаления контейнеров
docker compose start                     # повторный запуск
docker compose down                      # удаление контейнеров, данные остаются
```

После изменения `.env` пересоздайте контейнер бота — обычный `restart` новые
переменные не применяет:

```bash
docker compose up -d --force-recreate bot
```

Для обновления кода сначала сделайте резервную копию, затем замените исходники,
сохранив `.env` и `data/`, и выполните:

```bash
docker compose up -d --build bot
docker compose logs --tail=100 bot
```

Изменение паролей MySQL в `.env` не меняет пароли внутри уже существующей БД:
они применяются образом MySQL только при инициализации пустого тома. Плановую
смену паролей выполняйте одновременно в MySQL и конфигурации бота.

Резервное копирование и перенос на другой сервер описаны в
[docs/operations.md](docs/operations.md). Для старой версии с каталогами
`groups/`, `archive/`, `runtime/` в корне там же приведён порядок переноса.

## Если не запускается

| Симптом | Что проверить |
| --- | --- |
| Compose пишет `Fill ... in .env` | Заполнена ли указанная переменная; текущий каталог содержит `.env`. |
| `Permission denied` для `/app/data` | Владелец каталогов данных на Linux — UID/GID `10001`. |
| Ошибка Telegram API ID / токена | `API_ID`, `API_HASH`, `BOT_TOKEN` получены для нужного приложения и бота. |
| MySQL `Access denied` | Пароль в `.env` совпадает с паролем уже созданного пользователя БД. |
| Бот в группе, но переписки нет | Права бота в группе и фактическое получение обычных сообщений. |
| Нет меню / личного отчёта | Правильные числовые ID в `.env`; пользователь отправил боту `/start`. |
| Ошибки OpenAI в логах | Ключ, доступность API, доступ к модели и лимиты проекта. При ошибке текст считается деловым. |
| `database is locked` для сессии | Нет второго процесса с той же Telegram-сессией. |

Для локальной разработки и запуска тестов см. [docs/development.md](docs/development.md).
